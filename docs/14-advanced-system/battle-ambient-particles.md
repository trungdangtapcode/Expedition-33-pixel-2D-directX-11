# Battle Ambient Particles

## Goal

Turn-based battles need atmospheric motion without mixing visual effects into the combat simulation. The leaf particle feature adds two world-space draw layers:

1. Back layer: drawn after the battle background and before combatants.
2. Front layer: drawn after combatants and before the authored foreground.

This order lets leaves pass both behind and in front of characters while the environment foreground can still cover everything as the closest authored art.

## Runtime Ownership

`BattleState` owns one `BattleAmbientParticleRenderer`.

`BattleState` does not name a particle config directly. It loads the selected
battle environment first, then reads the optional environment field:

```json
"ambientParticleConfig": "data/battle_ambient_particles.json"
```

If the field is missing or `null`, that battle environment has no ambient
particles. This keeps the visual treatment data-driven per battle scene.

The fallback battle environment is also data-driven through:

```json
"defaultEnvironmentPath": "assets/environments/battle-paris-view.json"
```

in `data/battle_system_config.json`.

The renderer owns only visual resources:

- `SpriteBatch`
- `CommonStates`
- one particle texture SRV
- deterministic particle descriptors for each layer

It does not read or mutate `BattleManager`, `IBattler`, inventory, save data, action queues, or turn order. This keeps ambient motion independent from battle rules.

## Render Order

The battle frame is now:

```cpp
mEnvRenderer.RenderBackground(camera);
mAmbientParticles.Render(ctx, camera, BattleAmbientParticleLayer::Back);
mBattleRenderer.Render(ctx);
mAmbientParticles.Render(ctx, camera, BattleAmbientParticleLayer::Front);
mEnvRenderer.RenderForeground(camera);
```

This is a draw-order solution instead of a depth-buffer solution. The project already renders 2D sprites through DirectXTK SpriteBatch with explicit passes, so ordered passes are simpler and match the existing architecture.

## Data

The Paris battle environment selects the current config from:

```text
assets/environments/battle-paris-view.json
```

That environment points to:

```text
data/battle_ambient_particles.json
```

Important fields:

- `enabled`: Turns the effect on or off.
- `texturePath`: Particle texture, currently `assets/environments/leaf_particle.png`.
- `backCount` / `frontCount`: Density per layer.
- `worldLeft`, `worldRight`, `worldTop`, `worldBottom`: Spawn and wrap bounds in battle world coordinates.
- `minFallSpeed`, `maxFallSpeed`: Vertical speed range.
- `minDriftSpeed`, `maxDriftSpeed`: Sway frequency range.
- `minSway`, `maxSway`: Horizontal sway amplitude.
- `backMinScale`, `backMaxScale`, `frontMinScale`, `frontMaxScale`: Depth scale ranges.
- `backAlpha`, `frontAlpha`: Layer opacity.
- `windX`: Shared horizontal wind drift.
- `rotationSpeed`: Maximum spin rate.

The renderer clamps unsafe values and swaps min/max pairs when authored backwards, so a bad config does not crash the battle state. It does not provide a built-in texture path or density fallback; visible particles come from the environment-selected JSON file.

## Asset Pipeline

The leaf texture is generated by:

```text
tools/draw_battle_leaf_particles.py
```

It writes:

```text
assets/environments/leaf_particle.png
```

The runtime never depends on the script. The script exists so the source of the generated PNG is reproducible when the leaf silhouette or palette changes.

## Motion Model

Each particle stores deterministic seed values generated from its index. Per-frame position is derived from:

- the stable seed
- elapsed battle time
- configured speeds and bounds

This avoids accumulating per-particle drift and keeps the effect deterministic across frame rates. `Update(dt)` only advances a shared elapsed-time clock, so the system remains frame-rate independent.

## Camera Integration

Particles are world-space sprites. `Render()` passes `camera.GetViewMatrix()` to SpriteBatch, matching the project's world-space rendering rule:

```text
world -> screen pixels -> SpriteBatch viewport transform -> NDC
```

Do not pass `GetViewProjectionMatrix()` here. That matrix is already projected and would be projected again by SpriteBatch.

## Extension Pattern

To make ash, snow, embers, or magical dust:

1. Generate or author a new transparent texture.
2. Create a new particle JSON file.
3. Point that battle environment's `ambientParticleConfig` at the new JSON.
4. Tune the JSON values for density, speed, sway, scale, and alpha.

If multiple simultaneous particle types are needed later, prefer adding an array of effect configs to the renderer rather than creating battle-specific branches in `BattleState`.
