# Currency Wallet System

## Goal
The player needs a visible coin balance before shops and paid upgrades can feel fair. This system adds a durable `Wallet` service, data-driven enemy coin rewards, a generated coin icon, and HUD surfaces that show the current balance during exploration and at campfires.

## Runtime Ownership
`Wallet` is the single authority for the coin balance:

```text
src/Systems/Wallet.h
src/Systems/Wallet.cpp
```

It mirrors the ownership style of `Inventory`: states and battle systems do not store their own money values. They only call `Wallet::Get()` to read, add, set, or spend coins.

## Save Data
Save slots write a top-level `coins` field:

```json
{
  "schemaVersion": 1,
  "coins": 60
}
```

The schema version stays `1` because old saves can still load safely. If an older save has no `coins` field, `SaveManager` restores the starter wallet balance instead of failing the load.

## Rewards
Enemy slot data now supports:

```json
{
  "expReward": 45,
  "coinReward": 12
}
```

`JsonLoader::LoadEnemyEncounterData` parses `coinReward` into `EnemySlotData`. `BattleManager` totals the reward pool for the encounter and grants it only after victory. Defeat grants no coins.

## HUD Rendering
The visible coin readout is handled by:

```text
src/UI/CurrencyHudRenderer.h
src/UI/CurrencyHudRenderer.cpp
data/currency_hud.json
```

The renderer loads the icon path and layout from `data/currency_hud.json`, then draws a coin icon and the localized `currency.coins` label.

Current placements:

- Overworld top-right HUD.
- Campfire menu panel.

## Asset Pipeline
The coin icon is generated by:

```text
tools/draw_coin_asset.py
```

Output:

```text
assets/UI/coin_icon.png
```

The script uses Pillow to create a small transparent PNG with a readable pixel-art coin. Regenerate it by running:

```bat
python tools\draw_coin_asset.py
```

## Localization
The balance label uses:

```text
currency.coins
battle.log.coins_earned
```

Every shipped language table must include those keys so the HUD and victory log remain localized.

## Extension Points
Future campfire shops should call `Wallet::SpendCoins(cost)` before adding purchased items to `Inventory`. Character upgrades should use the same spend path before applying permanent progression through `PartyManager`.
